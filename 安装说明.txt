ComfyUI-H3-Director v2.40.2 安装说明
====================================

一、安装前确认

1. 建议 ComfyUI 版本 0.31.1 或更新版本，最低支持 0.30.0。
2. ComfyUI 中应能找到以下原生节点：
   - MiniMax H3 Reference To Video
   - MiniMax H3 Image To Video
3. 本插件不包含 H3 模型、VAE 或第三方加速插件。

二、安装插件

1. 完全关闭 ComfyUI。
2. 解压压缩包，确认得到文件夹：ComfyUI-H3-Director
3. 把整个文件夹复制到：
   ComfyUI\custom_nodes\ComfyUI-H3-Director
4. 如果电脑中已有旧版，建议先把旧文件夹改名备份，再复制新版；不要把新版和旧版文件混在同一目录。

三、安装依赖

在 ComfyUI 根目录打开终端，使用 ComfyUI 自带 Python 执行：

Windows 便携版常见命令：
python_embeded\python.exe -m pip install -r ComfyUI\custom_nodes\ComfyUI-H3-Director\requirements.txt

如果你的 python_embeded 位于其它位置，请把命令中的路径换成实际路径。

说明：只安装导演台 ZIP 时，requirements.txt 仍用于正常的手动依赖安装。若使用与本版配套的
“H3-Director-离线环境包.zip”，导演台只会对缺失模块使用包内固定 wheel，并强制
pip --no-index --no-deps；它不会联网寻找、升级或替换已经可以导入的依赖。

四、首次启动

1. 重新启动 ComfyUI。
2. 浏览器执行 Ctrl+F5 强制刷新。
3. 搜索节点“H3 漫剧导演台”或 H3DirectorStudio。
4. 节点顶部应显示 v2.40.2；若提示前后端版本不同，请再次完全关闭并重启 ComfyUI，然后 Ctrl+F5。

API 与 AI 功能：
v2.40.2：顶部“全部启用”只控制视频段是否参加运行和合并；二采卡使用独立“全部二采”。关闭全部二采会移除各段二采标记但保留每段原参数，重新开启时逐段恢复；没有历史参数的段使用当前二采默认。二采开关不会改变视频段启用状态，创作、视频、文本三个页面互不影响。此次前端修复不改变 2.40.1-056 离线环境包合同，原不含权重环境包仍可使用。
v2.40.1：另一台电脑的一键配齐界面只显示后端当前可用的环境来源；尚未加载兼容3D节点时通常只显示“本地离线环境包（不含权重）”。环境安装和权重下载分别显示状态，权重失败不再冒充环境失败。国内 ModelScope 固定权重允许在可信 HTTPS 域名内有限跳转，最终仍校验固定大小和 SHA-256，不会静默切换线路。离线环境包继续不包含3D权重；安装环境后仍需按明确选择的国内或官方线路联网下载权重。

v2.40.0：本地二采环境入口改为单个“环境包 ZIP”。用户只需先安装导演台 ZIP，启动后在“环境与3D权重”选择“本地离线环境包（不含权重）”，点“选择环境包 ZIP”，选择国内或官方权重线路，再点一键配齐。环境包固定包含二采加噪节点、与当前导演台合同兼容的3D节点快照和 Windows x64 / CPython 3.13 离线 wheels，不包含3D权重；后端先校验安装环境，再由导演台按所选在线线路下载并校验固定3D FP16权重，不静默换线路、不自动重启。作者3D节点无可核验LICENSE，因此该快照只限用户自有电脑私人迁移，不得据此公开发布或再分发。

v2.39.9：创作、视频、文本三页的统一设置和逐段设置均增加“二采采样方式”。默认“优先分块（2块，省显存，推荐）”，旧工作流无该字段时也按此执行；满足现有安全条件时在同一次二采内做两块空间采样和 latent 重叠融合，条件不满足会回到整幅。“整幅一次采样（高显存）”会禁用分块并只调用一次 H3 二采，但需要更多显存，不承诺16GB显卡一定能运行，也不宣称画质一定更高。两种方式都不改变模型、LoRA、注意力后端、时长、帧数、分辨率、步数、denoise、seed或固定沿用的一采音频。

v2.39.8：创作、视频、文本三页删除“冻结一采音频”选择，二采固定只修视频并沿用一采对白、音色和环境声；旧配置中的 freeze_audio=false 也会自动按 true 执行，不再重新采样音频。“多段统一设置 / 多段分别设置”下拉改成“多段统一设置”勾选框，勾选为统一、取消为分别，旧工作流属性保持兼容。本次不改变模型、时长、帧数、尺寸、步数、denoise、LoRA、注意力后端、DynamicVRAM、seed或画面采样数学；Live UI和真实GPU仍需验证。
v2.39.7：二采空间分块同步裁切 FL2VA 硬首尾帧条件，并在控制台和终态诊断记录分块方式、当前块或未分块原因。二采失败后不再在一采写盘前执行额外的无保护 CUDA 缓存同步；只有 MP4 实际写出后才显示“一采已保存”，CUDA 清理失败会明确说明。本次不改变模型、尺寸、帧数、步数、denoise、LoRA、注意力后端、DynamicVRAM、音频、seed或采样数学；真实 GPU 连续生成仍需验证。
v2.39.6：二采卡曾把“全部选择”接到视频段启用状态；该重复行为已在 v2.40.2 改为独立“全部二采”。
v2.39.5：创作、视频、文本三页各自显示“全部启用 / 全部尾帧”两个当前页勾选框，取代四个常驻批量按钮；每张时间线段卡也有独立“尾帧”勾选。第1段没有上一段尾帧，固定不可选；单段页面禁用“全部尾帧”。这些操作只影响当前页面自己的分段，独立视频超分页不显示。

五、创作页二次采样

1. 创作、视频、文本三个页面共用同一套二采设置、环境状态和运行门禁。普通生成不需要安装二采组件或二采模型；二采模式为“关闭”时，导演台使用原生成链。
   v2.39.1 起，“保存二采设置”同时保存当前节点的新段默认；以后新增创作页、视频页或文本页分段都会复制该配置并立即显示绿色“二采”。单段关闭或修改不会改变默认，再次保存才更新未来新段。
2. 当前二采链固定为：约0.4MP低分辨率首采 → 学习型3D latent放大到最终宽高 → 独立高分辨率repair conditioning → 低降噪整段缺陷修复二采。它不是同尺寸重采，也不是对MP4做插值超分。
3. 二采需要提供 MinimaxH3LatentUpscaler3D 的 Comfyui_Minimax_h3_latent_Upscaler 插件。官方在线
   来源不会自动安装该节点；可以手动安装，也可以使用本版配套的离线环境包做私人迁移。该节点
   仓库没有可核验 LICENSE，离线环境包里的兼容快照只限用户自有电脑之间迁移，不得公开发布、出售、
   镜像或上传。权重放在当前 ComfyUI 配置的 latent_upscale_models 目录，常见位置为：
   ComfyUI\models\latent_upscale_models
   固定在线catalog当前只有 MiniMax H3 3D latent upscaler FP16：文件名
   minimax_h3_latent_upscaler_3d_fp16.safetensors，大小690592672 bytes，SHA-256为
   043e5a48e161610ef6c3ea974645220354d06fa618abca15f76d084812eb55c2，catalog声明许可证
   Apache-2.0；国内ModelScope与官方Hugging Face都使用固定提交和固定下载合同。
4. 面板只有一个“开始一键配齐”入口。官方在线来源仍显示权重下载线路（国内/官方）和固定3D权重，
   并要求本机已加载 MinimaxH3LatentUpscaler3D；国内环境源未配置，国内只作为可选weight_source。
   本地来源改为“本地离线环境包（不含权重）”，仍需明确选择国内或官方在线权重线路。
5. 选择“本地离线环境包（不含权重）”后只显示一个“选择环境包 ZIP”文件入口，同时保留权重线路和
   固定3D权重选择。浏览器不把文件对象、文件内容或绝对路径保存到工作流。后端要求固定
   h3-director-environment-manifest.json、包ID/版本、
   精确文件路径、大小和SHA-256；额外文件、路径穿越、符号链接、加密项或不同文件会被拒绝。相同文件
   跳过，同名不同内容停止，不覆盖用户目录；缺失节点先写同目录暂存文件，校验后原子落位。任何
   weights/ 文件都会因不在环境清单内而被拒绝。只有缺失 Python 模块才从包内固定 wheel 执行
   pip --no-index --no-deps；环境完成后，导演台才按用户选择的在线线路下载并校验权重。完成后必须由
   用户手动重启 ComfyUI；导演台不会自动重启。
6. 离线环境包固定用于 Windows x64 / CPython 3.13，包含 MiniMaxH3AddNoise、
   MiniMaxH3ShiftSigmas、兼容 MinimaxH3LatentUpscaler3D，以及 imageio-ffmpeg、
   opencv-python、numpy、einops、safetensors 的固定 wheels。它不包含 ComfyUI 内核、H3 Base/Ref2VA
   主模型、3D权重、文本编码器、VAE、LoRA、SageAttention、PyTorch、CUDA或显卡驱动；目标电脑仍需
   已有兼容 ComfyUI 和 H3 主模型环境，并需联网让导演台下载固定3D权重。
7. 后端报告的已安装本地3D FP16权重会按真实文件名显示；新二采配置必须明确选择，并把纯文件名
   保存到当段 second_sample.upscaler_model。选择已安装本地权重时，普通在线环境不会再次调用
   /setup；若同时选择本地环境包，/setup 只安装环境并跳过权重下载。它不会把本地文件冒充成在线
   catalog条目；在线权重安装只接受同一次状态响应中真实存在的official环境、国内或
   官方权重源，以及固定weight_id=minimax_h3_latent_upscaler_3d_fp16。缺少upscaler_model时禁止
   保存/运行，不会按目录排序自动选第一个。旧≤3配置只有在恰好一个合法本地权重时才可确定性
   迁移，多权重时必须选择。按钮不安装H3 Base/Ref2VA主模型、ComfyUI、Torch/CUDA/驱动或API
   配置，不后台联网、不静默换线路，也不自动重启。
8. “一采像素目标”默认0.4MP；新二采默认“按百万像素”1.0MP，每段继承自己的横竖画幅，
   再把实际宽高对齐到32。MP、最终宽度和最终高度都可直接手动输入：开始编辑MP会自动切换
   到MP模式，开始编辑宽或高会自动切换到“按最终宽高（手动分辨率）”。切换模式沿用当前显示
   的实际尺寸/MP，避免明显跳变；最后编辑的类别接管单一真值。MP模式只保存MP，宽高模式只保存最终宽高。旧工作流
   已有 final_width/final_height 时会保持原尺寸并迁移为宽高模式，不会静默变成1.0MP。
9. 对齐后二采的宽、高和总像素必须全部严格大于一采，否则保存和运行都会被阻止并提示提高二采MP或
   最终宽高。实际二采超过2MP时只提示显存风险，不会自动降低分辨率、步数或降噪。
10. 轻度修复为5步/0.15，标准修复为7步/0.22，强力修复为9步/0.30；数值越高，修复自由度和漂移风险越大。默认使用标准修复并保存一采对比；二采固定沿用一采音频，不再提供开关。
11. 默认修复要求覆盖结构畸形、重影、重复或缺失部件、破损边缘、纹理断裂和闪烁，并要求保持剧情时序、运镜、构图、主体身份、服装、动作、场景、风格和正常区域。当前是整段修复，不会自动检测并只重画某一帧或某一块区域。
12. 勾选“保存一采对比”后，同一任务会先保存严格同源的“一次采样”历史版，再保存“二次采样”当前版；最终合并使用二次采样版。二采失败时会保留一采并明确报错，不会把一采伪装成二采成功。
13. 二采与“视频超分”是两套独立功能：二采发生在 H3 latent采样链内并能改变生成结构，视频超分只处理已生成的MP4，二者不会互相替代。
14. 正常CUDA/ROCm显存模式下，3D upscaler按ComfyUI能力选择FP16/BF16/FP32；LOW_VRAM、NO_VRAM、CPU、MPS、DirectML、XPU和NPU会让外部3D upscaler回退CPU FP32，速度可能明显变慢。运行报告会记录实际设备与精度。
15. v2.36.1 的二采阶段依次显示：释放一采运行资源 → 3D latent放大 → 释放放大临时资源 →
    准备H3二采模型 → H3二次采样N/总步数 → 恢复一采音频。实时状态只接收当前
    prompt_id、主导演台display_node、project_id和segment_index都匹配的事件；漏过实时事件时，
    只从 /status 的 second_sample_diagnostics.terminal_event 回读同形终态，不从错误文字猜OOM。
16. v2.37.4 在一采结束、进入3D latent放大前，先复用ComfyUI正常节点结束时使用的动态cast buffer
    重置和预取队列清理，解除一采遗留的预取固定页，再卸载其它可释放模型；仍有显存短缺时只有限
    释放同一个H3，不完整unload_all_models，也不直接操作私有VBAR/dynamic_pins。作者3D节点返回中间
    设备latent后，只删除本次权重文件名、CUDA设备和精度对应的MODEL_CACHE项，再由标准采样准备复用
    原H3、LoRA和attention patch。二采早期失败的诊断字段仍完整初始化并安全汇总，原始异常和一采
    结果不会被KeyError: upscaler_cache_release覆盖。
17. v2.37.5 移除了二采失败清理中的 unload_all_models。2.37.4 的真实日志证明，该完整卸载会在
    DynamicVRAM恢复模型备份时触发Fatal Python error: Aborted，使8188服务退出并遮蔽原始二采异常。
    新路径只清理失效模型记录和allocator缓存，让控制流到达ComfyUI官方节点结束边界；是否解决最初
    的二采错误仍需真实GPU复核，不能仅凭自动测试称为修复成功。
18. v2.38.0 的真实15秒任务证明，把一采、作者3D放大和H3二采拆成三个内部节点仍不能解决问题：
    H3首次高分辨率forward达到18.04 GiB并在0/7 OOM。当前ComfyUI的节点结束只重置动态cast buffer、
    预取队列和VBAR水位，不会卸载H3 ModelPatcher，因此v2.38.1已删除该三节点路径，不再继续增加
    节点数量或重复旧清理方案。
19. v2.38.1 仅对沿用一采音频、denoise不高于0.35、没有参考图片、视频latent为5D且空间长边至少64的
    二采启用导演台内置空间分块：沿长轴分两块，每块使用同一个H3、LoRA、attention patch、repair
    conditioning、sampler、scheduler、seed和完整steps，8个latent token重叠后余弦融合，再拼回原一采
    音频。它不依赖YCNodes，不降低帧数、最终宽高、steps、denoise或精度；两块分别采样可能更慢，
    接缝、画质、峰值显存和连续生成是否成功仍需真实GPU验证。条件不满足时保留原单次二采路径。
20. 结构化OOM会明确显示“一采已保留、二采未完成、运行态已释放”。自动测试锁定5秒成功配置
    （124帧、一采25步、latent 56×28→128×64、目标2048×1024、二采8步）和15秒362帧配置
    不被修改；真实5秒/15秒显存、速度和OOM改善仍未做GPU验证。12秒及以上且达到约2MP的二采
    会提示16GB级显卡也可能OOM，但不会自动降低帧数、尺寸、步数或改采样参数。

六、视频超分模型

1. 没有安装 UPSCALE_MODEL 时，只能使用“Lanczos普通放大”。Lanczos 会增大视频分辨率，但不会生成新的人脸、纹理或真实细节。
2. 打开导演台“视频超分”页，在模型目录中选择类型，再点“一键国内安装”。只有这次明确点击才会访问固定魔搭仓库；打开页面、恢复工作流或刷新模型列表都不会联网。
3. 下载完成后会核对固定文件大小和 SHA-256，再安装到当前 ComfyUI 配置的第一个 upscale_models 目录；不接受任意下载地址，也不会覆盖同名模型。
4. 也可点击“安装本地模型”，主动选择已有的 .pth、.pt 或 .safetensors 文件。插件仍会使用当前 ComfyUI 配置的 upscale_models 目录且不覆盖同名文件。
5. “删除模型”只删除“超分模型”下拉框当前选中的本地模型。前端会显示精确模型名并二次确认，不会删除文件夹或其它模型。
6. 写实或通用 2×视频优先尝试 RealESRGAN_x2plus；动漫视频可尝试 RealESRGAN_x4plus_anime_6B。使用 4×模型但输出倍率设为 2×时，会先进行模型超分，再缩放到目标尺寸。
7. AI 超分才可能恢复或生成可见细节，但也可能过度锐化、改变线条或产生伪细节。请在相同显示尺寸下比较人物脸部、发丝、文字和建筑边缘；严重失焦或已经丢失的细节不能保证修复。
8. 模型下载、校验、安装和刷新状态会直接显示在模型按钮下方；模型列表读取超过 8 秒会明确报超时，不会无限停在“正在刷新”。
9. 处理进度分为逐帧超分、编码保存和完成。成功后不会弹出新窗口；右侧“超分结果”区域会直接显示原视频/超分视频拖动对比。两段视频同步播放，只有原视频发声。v2.35.1 起，超分结果和“新窗口查看”统一通过插件只读视频路由打开中文 MP4；只有原视频和超分视频都读到有效元数据后才启用同步播放，路由、解码、格式或时长异常会直接显示。新文件不会覆盖原视频。

七、低显存与内存说明

1. 当前版本已删除导演台顶部“8GB优化”和“FFN分块(实验)”按钮，不再自动限制步数、参考视频帧率/尺寸或修改模型计算。
2. 旧工作流中的隐藏8GB开关和段级FFN标记会被安全清理，现有工作流仍能加载。
3. 完整视频和音频保存在项目输出目录，全部生成或点击时间线段卡“重抽”后会自动按最新段文件合并完整 MP4。
4. v2.24.3 写视频时会把 RGB 帧逐帧发送给 FFmpeg，不再额外创建整段原始帧的连续 `bytes` 副本，可降低编码阶段的系统内存峰值；这不会降低 H3 推理所需显存，也不会改变画面、音频或编码参数。
5. 验证顺序是先复测同一5秒成功路径，再测试15秒；只有资源交接修复后的15秒仍OOM，才在上游
   单独测试一种KJNodes低显存节点。KJNodes没有被复制、自动集成或设为插件依赖，本轮也没有执行
   真实A/B。不建议同时叠加多个注意力补丁、编译器、缓存加速器或重复LoRA；导演台不会自动追加补丁。
6. v2.24.3 已移除 `Turbo LoRA + pruned_int8/pruned_fp8` 的旧硬拦截，兼容版本的 Turbo LoRA 节点可为 pruned 模型恢复所需时间条件层。导演台仍不能接管 Turbo 专用音频/video flow schedule，因此只保留非阻塞警告；特别是4步模式，请先用相同提示词和种子做短片 A/B，确认画面和模型原声后再用于正式生产。
7. v2.24.26 在每段安全写盘后自动轻量清理；只有内存压力、异常/取消或用户请求时才深度卸载。深度释放会让下一段重新加载模型，启动可能稍慢，但不会中断当前采样，也不改变画面、音频或采样参数。
8. “段后深度释放”只显示在视频界面。点击后不会立即清除正在使用的模型，而是在当前段完成并保存后执行；挂机任务即使无人点击，也会根据实际电脑内存压力自动保护。
9. 每段 MP4、尾帧和完成 JSON 会共同验证。前三段完成、第四段失败时，下次运行从第四段继续；损坏或未写完的 MP4 不会被当作缓存。

八、剧本与分镜导入

1. 文本页、创作页、视频页分别保存自己的内容；修改一个页面不会自动改动其它页面。
2. 横排七分类助手和 AI精修选中不再提供；创作页/文本页保留独立的 AI剧情、AI分镜、AI精修，并保留“导入当段”。两页不再显示 AI小说分析；旧脚本中已有的逐段尾帧计划仍可解析，待确认段默认关闭并提示人工确认。
3. 只有需要用完整脚本替换当前时间轴时才点“⚡ 解析导入”；已有旧段时再次点击红色按钮确认。脚本框有未导入修改时直接运行不会自动覆盖时间轴，而是按当前段提示词、当前分段和已挂参考素材执行。
4. 导演台支持官方 Base、官方 Ref2VA、中文档案分镜和普通文本；中文档案分镜不是官方模板。官方 Base 保留三字段，Ref2VA 保留六字段，后续 Shot 使用绝对时间。
5. 创作页提供“资产库”和“当前段实际参考”。图片默认只进入资产库，不会按提示词自动分配；可拖入指定分段。每张资产勾选“全局参考”后会进入所有创作分段，不勾选则只用于手动拖入过的分段。两个区域下方都有小拖动柄，可独立调整宽高并随工作流保存；该资产库不会出现在文本页或视频页。
6. 全局参考固定排在各段 Picture 编号前面。插件不会再按角色、场景、道具、通用分类或单段总数裁掉参考图，也不会因为数量撤销“全局参考”勾选。
7. 节点只保留一个主 `model` 大模型接口，同时保留 `clip`、`vae`、`audio_vae`。切换 Ref2VA 或 FL2VA 时只需更换连接到 `model` 的上游 UNet 模型；插件会根据主模型自动选择软参考或硬首帧路径。旧工作流残留的第二模型输入和 `ref_image_N` 图片输入会在界面恢复时自动移除。
8. 15/30/60/180秒均按源时间轴守恒；一个生成段内部的节拍不会再次拆成多个生成段。带权威时间码的脚本若明显膨胀，“解析导入”会拒绝覆盖当前时间轴。
9. 本版继续保留最终生成、单段重抽、自动合并、音频和输出视频；不在前台提供开发审核、修复或预检门禁。

九、API 配置

1. 插件包不包含任何 API Key，也不会自动带入作者电脑的配置。
2. 在导演台顶部工具栏下方的“API 设置”中填写你自己的 OpenAI 兼容 API 地址、模型名和 API Key；三个页面只共用连接配置，不共用页面内容。
3. 本地文件名、资产名、别名匹配、解析导入、时长检查和自动合并不需要 API。AI剧情、AI分镜、AI精修，以及创作页仍有不确定资产需要判断时，会调用当前保存的单一远程 API；失败时不会改写原文或注入完整资产库。
4. 若出现“Incorrect API key”或 401，请检查 API 地址是否属于购买 Key 的服务商；第三方 Key 不能直接发送到 OpenAI 官方地址。
5. v2.23.3 会优先使用系统代理；若代理在建立连接前失败，会自动直连重试一次。鉴权、余额、限流和模型错误不会自动重试，避免重复消耗额度。
6. API测试已经收到服务端响应、但只返回推理过程或空最终文本时，界面会显示“API已连接，但本次响应没有可用的最终文本”，不再误报网络连接失败。测试没有实际发送图片；绿色文案只会说明“按模型名称判断应支持参考图，首次带图生成时实际验证”。

十、跨电脑排错

1. 确认复制的是完整 ComfyUI-H3-Director 文件夹，不是只复制 web 或单个文件。
2. 确认依赖安装到了当前这套 ComfyUI 的 Python，而不是系统 Python。
3. 启动日志若提示缺少 H3 原生节点，请先更新 ComfyUI。
4. 若页面仍是旧界面，完全重启 ComfyUI 并 Ctrl+F5；仅刷新页面不会更新 Python 后端。
5. 请勿把 api_config.json、个人模型路径或旧电脑生成缓存复制进发布包。
